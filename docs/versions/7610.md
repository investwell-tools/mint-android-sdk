

## Overview

When integrating the Mint SDK, your app must declare the correct `application` class in `AndroidManifest.xml`. If your parent app already has an application class, extend the SDK’s base application class and point the manifest to your custom class. Android’s manifest merger also supports replacing conflicting attributes such as `android:theme` using `tools:replace`. 

A sample implementation and demo files are available in the shared Google Drive folder. Google Drive supports downloading shared files and folders directly from the browser. 

## Application class setup

If the SDK provides a base application class such as `AppApplication`, create your own application class and extend it. This lets you keep your app-specific initialization while preserving SDK requirements.

```kotlin
class Demo : AppApplication() {

    override fun onCreate() {
        super.onCreate()
        // Add your app initialization here
    }
}
```

## Manifest configuration

Update your `AndroidManifest.xml` to use your custom application class name. If your app theme conflicts with the SDK or other manifest entries, use `tools:replace="android:theme"` to resolve the merge cleanly. Android’s manifest merger is designed for exactly this type of override. 

```xml
<application
    android:allowBackup="false"
    android:label="@string/app_name"
    android:name=".Demo"
    android:supportsRtl="true"
    android:theme="@style/Theme.MintDemo"
    tools:replace="android:theme">
```

If you need to replace more than one attribute, you can list them together, for example `tools:replace="android:icon,android:theme"`. 

## MainActivity integration

Initialize the Mint SDK in your `MainActivity` and configure it before invoking the SDK flow.

```kotlin
class MainActivity : Activity() {

    private lateinit var mintSdk: MintSDK

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        mintSdk = MintSDK(this, MintSdkThemeMode.DARK).apply {
            configureSDK(isConfigured = true, customLoader = null) //customLoader null is default loader 
        }

        msession = AppSession(this)
    }
}
```

## Passing SSO and token

After the SSO token is generated, pass it to the Mint SDK together with the FCM token. In the example below, `TokenGenerator.generate()` use your own fcm token.

```kotlin
mintSdk.invokeMintSDK(
    sso = ssoToken,
    token = TokenGenerator.generate(),
    domain = "demo",
    classWithPackage = "${packageName}.MainActivity"
)
```

## Auth validation before SSO generation

Before generating the SSO token, check whether the SDK authentication has already been validated. This avoids unnecessary token generation and keeps the flow predictable.

```kotlin
if (!mintSdk.isAuthValidated()) {
    // your ssoToken generation code here
}
```

## Logout flow

Before logging out of the parent app, first clear the SDK session data. This ensures the SDK state is properly reset before your application performs its own logout logic.

```kotlin
mintSdk.clearSDKData()
```

## Notes

- Replace `.Demo` with your actual application class name if you use a different one.
- Keep `tools:replace="android:theme"` only when you need to override conflicting theme attributes.
- Ensure the `MintSDK` initialization happens before calling `invokeMintSDK`.
- Call `clearSDKData()` before the parent app logout flow to avoid stale SDK state.
